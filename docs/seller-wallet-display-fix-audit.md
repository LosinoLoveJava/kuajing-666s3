# 商家钱包记录显示修复

日期：2026-10-23。

## 范围与诊断

用户确认入口：`https://admin.pddglobalmerchanthub.com/seller/money-withdraw-requests`。

商家页加载 `aiz-seller.css`，独立于之前修复的管理端 `aiz-core.css`。该样式仍将 `.aiz-table` 默认设为透明、高度为零，依赖 FooTable 初始化后才显示。使用线上已有商家、独立临时文件会话及禁用 JavaScript 的浏览器上下文，复现钱包和支付历史页面返回 HTTP 200、HTML 含记录但表格计算透明度为 0。脚本正常初始化时记录可显示，因此没有将本次诊断解释成所有请求都查不到数据。

只读查询抽查商家有 15 条充值、18 条提现申请、32 条支付记录；全部商家的充值记录合计 18 条、支付记录合计 44 条。没有发现需要补写历史财务数据的证据。

## 修复

- 商家表格默认可见，钱包 CSS 使用新的版本参数避免继续命中旧缓存。
- 钱包四个列表及独立支付历史使用服务端横向滚动容器，脚本未运行时也可查看全部列。
- 真正空列表显示明确提示，独立支付历史不再仅显示空白卡片。
- 各列表按时间及 ID 倒序稳定分页，序号按当前页连续计算；四个钱包分页保留独立参数和其他列表页码。
- 修正钱包内容容器在 modal 区域才闭合的标记问题。
- 所有查询继续限制当前登录商家。没有变更余额、入账、退款、提现审核逻辑，也没有执行数据库迁移。

生产 PHP 语法、Blade 预编译、七个入口、商家 CSS 的源站及公网/CDN SHA-256 检查通过。浏览器旧主页面在发布暂停 Web 期间累计的自动轮询网络错误未作为新页面功能失败，也没有据此宣称整轮浏览器控制台零错误。验证使用现有业务数据，没有创建或删除生产业务记录。

## shoptest1 后续定位：收支明细误用充值数据源

用户补充店铺 `shoptest1`、通过管理员“登录商家”进入。只读诊断确认该店铺属于用户 693，充值 0 条、提现申请 2 条、商家支付 3 条。实际从管理员商家列表点击该店铺的“以此卖家身份登录”，商家标题与身份均正确；原提现历史及支付历史分别显示 2 / 3 条，并未复现代登录账号错乱。

浏览器中文截图揭示具体问题：`Wallet Recharge History` 的数据库中文翻译为“钱包收支明细”，但控制器只传入 `wallets` 充值记录。该店铺没有充值，所以这一栏一直为空，之前表格可见性修复没有解决这个数据范围与标题不符的问题。

本次新增真正的“钱包收支明细”，按时间合并当前商家的充值、提现申请及商家支付记录。三个来源分别限制当前账号，支付沿用 `t_type=1` 限制；SQL UNION ALL 后在数据库分页，独立参数为 `hpage`，相同时间按来源和 ID 稳定排序。各记录显示来源类型与真实审批状态；提现申请与支付凭证保留为不同类型，没有新增金额汇总或将两者重复计为余额变动。原充值列表保留全部明细字段，中文标题改为“钱包充值记录”。两个标题使用文件语言资源，避免继续复用错误的数据库翻译。

新增无充值但存在提现/支付的回归、混合来源分页、商家隔离及中文标题检查。钱包、账务流程、充值表单、门户隔离及商家首页性能测试共 68 项、623 次断言通过。报告：`output/local-runtime/shoptest-wallet-verified-tests.xml`。
