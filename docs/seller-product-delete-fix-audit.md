# 商家产品删除 404 修复

日期：2026-10-23。

## 诊断与修复

线上日志中，商家产品列表返回 200，随后 `/seller/products/destroy/{id}` 请求自身返回 404；只读核对发现该产品仍存在，因此不能将这一次请求认定为已删除成功后的跳转故障。

确认原代码有三个相关问题：

- `IsSeller` 对未登录/会话失效的请求直接返回 404，线上匿名访问商家产品列表也复现了此行为。现在转到商家登录页；删除入口记录的登录后返回位置为产品列表，避免重新执行删除 URL。
- 删除入口使用 `findOrFail()`，重复点击已删除的产品会返回 404。现在提示无记录并返回产品列表。
- 删除成功、失败或归属不符时使用 `back()`，返回地址可能是删除入口或已经失效的产品编辑页。现在统一返回 `seller.products`。

保留原产品归属、账号禁用和角色检查，以及产品翻译、库存、税费和购物车关联记录的删除逻辑。

## 验证

- 新增 `SellerProductDeletionTest`：12 项测试、104 次断言通过，使用独立 SQLite 内存库和真实 HTTP 路由/权限中间件。覆盖删除及关联清理、再次删除、其他商家产品、失效会话、其他角色、禁用账号，以及管理域名下的商家页面。
- 与多端会话隔离、会员功能回归一起运行：41 项测试、521 次断言通过。
- 发布前预检只发现本次两个后端文件差异；生产 PHP 语法、Blade 预编译、七个公开入口、源站/CDN 静态资源校验均通过。
- 发布后，商家域名和管理域名下，已登录请求不存在的产品 ID 均返回 302 至产品列表，最终页面 200 且表格可见；匿名产品列表和删除入口均返回 302 至商家登录，最终页面 200。
- 线上测试 ID 经只读查询确认不存在；实际产品删除和关联清理在独立测试库验证，未删除真实线上产品。原日志涉及的产品仍在。
- 验证使用独立临时商家文件会话，结束后销毁；未修改账号或数据库结构。
