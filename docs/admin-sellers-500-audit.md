# 管理端卖家列表 500 修复

日期：2026-10-23。

## 根因与修复

修复前使用独立临时管理员会话请求 `/admin/sellers`，源站返回 500，列表仅渲染到第 4 行；同一时刻 Laravel 生产日志记录 PHP 耗尽 256 MB 内存。

原模板通过 `$shop->user->products->count()` 统计商品，实际会加载该卖家的全部商品以及默认预加载的商品翻译、税费。充值和提现统计同样加载全部明细再逐条累加。分页仅限制店铺数量，没有限制这些关联数据的内存占用。

修复后的控制器只加载当前页用户，使用数据库 COUNT/SUM 计算商品数量、充值和提现。充值仍只计入审批通过的数据，排除 `seller_order_reward`，保留付款方式为 NULL 的历史数据；提现仍只计入成功记录，页内合计规则保持一致。

同时补齐模板所需的日期、业务员、虚拟账号和审批筛选变量及查询逻辑；搜索改用子查询而非物化用户 ID 数组；业务员统一预加载，缺失父账号显示 `---`，名称输出转义。修复审批值 0/1 的选中状态和空业务员参数。

## 验证

- 新增 `tests/Feature/AdminSellerListingTest.php`，12 项测试、54 次断言通过，覆盖空结果、缺失父账号、财务计算、筛选 0 值、输入校验及大量商品场景。
- 与卖家首页性能、多端会话隔离测试一起运行：37 项测试、408 次断言通过。未重复运行已知存在历史失败的全量测试。
- 本地只读数据库完整渲染：12 行，控制器 5 条查询、69.78 ms；含布局总计 19 条查询、1186.21 ms，峰值内存 42 MB，保持 256 MB 内存上限。
- 线上修复后默认列表返回 200、12 行，源站内网 HTTP 耗时 888.55 ms。分页、审批 0/1、普通/虚拟账号、无结果搜索及日期筛选均返回 200。
- 线上控制器只读采样：5 条查询、35.6 ms，CLI 进程峰值内存 26 MB，未加载商品或财务明细集合。该内存数字不等于完整 HTTP 请求内存。
- 验证使用临时文件会话，结束后销毁，不修改真实账号、密码或登录状态。
